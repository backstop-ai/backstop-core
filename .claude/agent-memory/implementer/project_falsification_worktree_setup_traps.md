The detached-worktree-at-HEAD pattern is the only way to get an attributable gate reading in
a contended shared tree (see [[project_redproof_by_worktree_flip]],
[[feedback_never_stash_shared_tree]]). Setting one up hit THREE traps in a row on
ISSUE-067, all of which produce a WRONG-BUT-PLAUSIBLE result rather than an error.

**1. `ln -sfn <src> .backstop` SILENTLY NESTS.** If `.backstop` already exists as a real
directory, `-n` does not save you — the link lands at `.backstop/.backstop` and the gate
dies with a confusing `declared pack <name> is missing from <worktree>/.backstop/packs`.
Read that message as "my symlink is wrong", not "the pack is missing". Verify with
`ls -la .backstop/` and confirm you see `packs -> ...`, not a nested `.backstop`.

**2. A gitignored `.backstop/baseline.json` makes the gate PERMISSIVE.** It is 240KB, it is
generated by other runs, and symlinking or copying the whole `.backstop` drags it in — so
the gate suppresses pre-existing findings and hands you a FLATTERING FALSE GREEN. For a
falsification reading, build `.backstop` deliberately: symlink ONLY `packs`, copy
`coverage-exclusions`, and provide NO baseline. Then every number is the strictest possible
and a clean result actually means something. See
[[project_local_baseline_makes_gate_permissive]].

**3. A hot file in the shared tree is NOT "HEAD + your diff".** `cmd/backstop/pack_gate.go`
carried a THIRD lane's uncommitted refactor (deleting `runNeverStarted` for
`check.NeverStarted`) on top of mine. Copying my working copy into the worktree would have
re-imported exactly the contamination the worktree exists to exclude. **Check before
copying:** `git diff HEAD -- <file> | grep '^-'` — if it REMOVES lines you did not remove,
the file is shared. The fix is to reconstruct: start from `git show HEAD:<file>` and
re-apply ONLY your own hunk, then confirm the resulting `git diff --numstat` matches your
change alone.

**How to apply:** after setup, before trusting any number, assert all three — `ls -la
.backstop/` shows a real `packs` link and NO `baseline.json`; `git status --porcelain` in
the worktree lists EXACTLY your files; and the numstat for any shared file equals your hunk.

**Corollary — attribute leftovers cheaply, don't rerun the world.** A full control
`gate --all` may not even be runnable (mine died at `pack_lock_verification` because
pristine HEAD's lock pinned the OLD pack version while the shared installed pack was
already upgraded). Targeted control checks are decisive and cost seconds: run the ONE
failing test in a pristine worktree, or enumerate the offending CONSTRUCTS in both files and
diff the sets. Say plainly which findings you proved that way and that you did NOT produce a
full control violation-set diff.
