# Baseline Generate Bypasses Effective Build Identity

## Problem

`cmd/backstop/root.go:20` declares the raw link-time build stamp:

```go
var version = "dev" // ...
```

`root.go:18` documents, at the declaration itself, that no caller should read this
variable directly: "Read effectiveBuildIdentity() (version.go) instead." `version.go:166`'s
`effectiveBuildIdentity()` is the resolver that honors that warning — its own doc comment
states it is "the ONE resolved identity every output surface reads, so no two of them can
report different versions than `backstop version` does," and it is the sole caller of
`debug.ReadBuildInfo`. Every real output surface follows that rule:
`output.go:119`/`output.go:233`, `doctor_checks.go:180`, `gate.go:359`, and `root.go:110`
itself all call `effectiveBuildIdentity()` rather than reading `version` directly.

`cmd/backstop/baseline.go:102`, inside `runBaselineGenerate`, does not:

```go
artifact := gate.NewBaselineArtifactFromSteps(result.Steps, time.Now().UTC().Format(time.RFC3339), gitSHA(projectRoot), version)
```

It passes the raw `version` package variable straight into the baseline artifact's
`BackstopVersion` field (`pkg/gate/baseline.go:23`, JSON key `backstop_version`), at a call
site inside the very file whose sibling declaration warns against exactly this.

For any binary built without the release pipeline's `-ldflags -X main.version=...` stamp —
e.g. `go install`, or CI running `go run`/`go build` from source rather than a tagged
release — `version` stays the literal string `"dev"` even though
`effectiveBuildIdentity()` can still resolve a real version from Go module build info.
`backstop version` and every other output surface correctly report the resolved identity;
only the published baseline's `backstop_version` field reports `"dev"`.

Confirmed live: `bclabs-brief-builder`'s first-ever CI-published `backstop-baseline-v1`
artifact (Acceptance run `33409042904`, downloaded and inspected 2026-08-31) carries
`"backstop_version": "dev"` in its `baseline.json`, while that same CI environment's
`backstop version` reports a real resolved version via `effectiveBuildIdentity()`. The
`backstop_version` field exists specifically so a baseline comparison can detect "this
baseline was generated by a different backstop version than the one comparing against it"
(`pkg/gate/baseline.go:23`); a field that reads `"dev"` regardless of which backstop
version actually generated the baseline cannot do that job.

## Not the same as ISSUE-130

`ISSUE-130` ("Pseudo Version Regex Gap Leaks Dev Fallback") widened `pseudoVersionSuffix`
*inside* the resolver so more VCS-synthesized pseudo-version forms are recognized and
rejected before falling back to `"dev"`. It fixed a gap in what
`effectiveBuildIdentity()` itself resolves. This issue is a different call site entirely:
`baseline.go:102` never calls the resolver at all, so no amount of correctness inside
`effectiveBuildIdentity()` can reach it. The two are adjacent (both are about the `"dev"`
fallback value reaching an output surface it shouldn't) but do not subsume each other —
ISSUE-130's fix, already delivered, does not touch `baseline.go` and would not have
prevented this.

## Solution

`runBaselineGenerate` should read `effectiveBuildIdentity()` (already done by every other
output surface in the package) and derive the baseline's `backstop_version` field from the
resolved identity rather than the raw `version` variable, at the `baseline.go:102` call
site. The specific field on `BuildIdentity` to use should match what `backstop version`
itself reports, so a baseline's provenance is never a version `backstop version` couldn't
also report.

## Verification

A regression test should build (or simulate) a baseline-generate run where the raw
`version` package variable is `"dev"` but Go module build info resolves a real version,
and assert the resulting `baseline.json`'s `backstop_version` field matches
`effectiveBuildIdentity()`'s resolved value rather than the literal `"dev"`. A release-style
build (raw `version` injected via `-ldflags`) should continue to report the injected
version unchanged, preserving injection-wins precedence.
