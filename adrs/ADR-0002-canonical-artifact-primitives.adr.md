# ADR-0002: Six Canonical Artifact Primitives With Machine-Enforceable Schemas

**Number:** ADR-0002
**Created:** 2026-03-17
**Status:** Accepted
**Deciders:** @bmanson
**Decisions:** D-001–D-008, D-036, D-072

---

## Context

AI coding agents need structured artifacts to operate deterministically. Freeform documentation — wikis, READMEs, design docs — is advisory by nature. An agent can read it, interpret it differently every time, and produce inconsistent output. There is no way to mechanically verify that an agent followed a Google Doc.

Backstop replaces advisory documentation with **machine-enforceable artifacts.** Each artifact type has a JSON schema, a template, and validation rules. Agents generate artifacts that conform to schemas. Validators reject artifacts that don't. The gap between "what we said" and "what we built" closes to zero because both are expressed in the same machine-readable format.

## Decision

### The six primitives

Backstop defines six canonical artifact types. Together they form a complete traceability chain from intent to implementation:

| Primitive | Purpose | Role in the chain |
|-----------|---------|-------------------|
| **ADR** | Records architectural decisions and their rationale | Foundational constraints that shape everything downstream |
| **Bundle** | Captures research, context, and domain knowledge | Thinking artifacts — the raw material specs are derived from |
| **Directive** | Declares a unit of intent — "do this thing" | The commitment artifact. Bridges thinking (bundles) and building (specs). Anchors a ledger. |
| **Spec** | Defines what to build with verifiable claims | The contract. Claims are mechanically verified against tests and standards. |
| **Plan** | Breaks a spec into ordered, executable tasks with file-level scope | The roadmap. Tasks enumerate files to touch, enabling concurrency analysis and progress tracking. |
| **Issue** | Captures bug fixes and small features for on-the-fly work | The lightweight sibling of specs. Same enforcement, less ceremony. |

An optional seventh primitive, **Capability**, declares what an agent can do. It is omitted from the manifest if not used — no enforcement, no complaints.

### The traceability chain

```
ADR / Bundle / Issue
       ↓
   Directive          ← unit of intent, anchors a ledger
       ↓
     Spec             ← verifiable claims, mandated test names
       ↓
     Plan             ← ordered tasks, file-level scope
       ↓
     Code             ← generated by agent, validated by backstop
```

Every artifact points to its parent:
- Directives cite source artifacts (bundles, ADRs, issues, or session timestamps)
- Specs reference an authorizing directive
- Plans reference a parent spec
- Code traces back through the plan to the spec to the directive

No orphans. Every piece of work is traceable to the intent that authorized it.

### Schema enforcement

Every artifact type has:
- **A JSON schema** defining its required and optional fields, types, and constraints
- **A template** for scaffolding new instances via `backstop new <type>`
- **A declared schema version** embedded in the artifact itself

Validators enforce the schema version the artifact declares, not the latest schema (D-036). A spec written against `spec@1.0.0` is valid forever as long as it was valid when created, regardless of what `spec@2.0.0` requires. Schema drift is a migration concern, not a validation failure.

### Naming convention

All artifacts follow a consistent naming pattern (D-072):

```
<ARTIFACT-TYPE>-<NNNN>-<semantic-slug>.<artifact-type>.<ext>
```

Examples:
```
ADR-0001-agent-first-discipline-framework.adr.md
SPEC-0001-claims-schema-validation.spec.md
PLAN-0001-backstop-validate-mvp.plan.yml
ISSUE-0001-validator-false-positive.issue.md
DIRECTIVE-0001-python-ast-analyzers.directive.md
BUNDLE-0001-backstop-primitives.bundle.md
```

- **4-digit zero-padded IDs** auto-increment per artifact type
- **Double extension** (`.adr.md`, `.spec.md`) makes the artifact type unambiguous in any file listing
- **Semantic slugs** are required — every artifact is human-identifiable by filename
- `backstop new <type>` auto-assigns the next available ID

### Directive as the anchor

Directives occupy a special structural role. They are:

1. **The entry point for tracked work.** Want to start something? Create a directive.
2. **The anchor for provenance ledgers.** Every directive gets a ledger file that records every action taken in service of that directive (see ADR-0009).
3. **The bridge between thinking and building.** Bundles are exploratory. Specs are contractual. Directives are the commitment that moves from one to the other.

Directive lifecycle: `queued → active → specced → done`

### Consuming repo layout

Projects using backstop organize artifacts under `.backstop/`:

```
backstop.yml                              manifest (project root)
.backstop/
  adrs/                                   architectural decisions
  bundles/                                context and research
  directives/                             units of intent
  specs/                                  implementation contracts
  plans/                                  task breakdowns
  issues/                                 bug fixes, small features
  ledger/                                 provenance ledgers (per directive)
  cache/                                  gitignored — recipe catalog, etc.
```

## Consequences

### What this enables
- **End-to-end traceability.** Every line of code can be traced back through plan → spec → directive → intent.
- **Agent determinism.** Structured schemas eliminate interpretation variance. Two agents reading the same spec produce compatible output.
- **Incremental adoption.** Teams choose which primitives to enable in `backstop.yml`. Enforcement-only teams skip specs and plans. Full-ceremony teams use everything.
- **Machine validation.** Every artifact can be validated against its schema without human interpretation.

### What this requires
- **Schema-first development.** Schemas must exist before artifacts. New fields require schema updates.
- **Version discipline.** Schema versions are immutable once released. Breaking changes require new major versions.
- **Template maintenance.** Templates must stay in sync with schemas.

### What this does NOT mean
- **All six primitives are required.** Teams configure which primitives they use. The only required artifact is `backstop.yml` itself.
- **Artifacts are heavyweight.** A directive can be three lines. An issue can be a paragraph. The schema ensures structure, not length.

## Alternatives Considered

| Approach | Why Rejected |
|----------|-------------|
| Freeform markdown docs | Not machine-enforceable. Agents interpret them inconsistently. No schema validation possible. |
| GitHub Issues / Jira as the artifact system | External dependency. Not agent-readable in context. Not colocated with code. Loses the traceability chain. |
| Single artifact type (just specs) | Conflates intent, research, decisions, and contracts into one shape. Different artifacts serve different purposes at different stages. |
| No schema enforcement (advisory templates) | Agents ignore suggestions. If it's not enforced, it doesn't happen. Advisory tools train humans; enforcement tools discipline agents. |
